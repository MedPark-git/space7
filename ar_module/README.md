# MedPark 채권관리

덴탈 · 메디컬 · 에스테틱 세 사업부의 미수채권 잔액과 수금 진행을 관리하는 사내 웹 애플리케이션입니다.
Flask(Python 3.11) + React 단일 페이지 구조이며, 데이터는 **PostgreSQL**에 저장합니다.

---

## 1. 배포 전에 반드시 읽을 것

### 시연용 데이터가 들어 있습니다
원본 엑셀(미수채권현황)에서 추출한 실제 거래처 372건은 **이 패키지에 포함되어 있지 않습니다.**
최초 실행 시 `seed.py`가 9개 분류(3사업부 × 3채권분류)에 걸쳐 시연용 거래처 94건을 만듭니다.

실데이터는 이렇게 넣습니다.

1. `Medpark0` 또는 `Medpark3`으로 로그인
2. **출고 데이터 업로드** 화면 → 기준월 선택 → 엑셀 파일 업로드
3. 시연용 데이터가 있는 월(최초 실행한 달)을 같은 기준월로 덮어쓰면 시연 데이터는 사라집니다

### 초기 비밀번호
소스와 화면에는 초기 계정 비밀번호를 저장하거나 표시하지 않습니다.
빈 데이터베이스에서 최초 계정을 만들 때만 `AR_INITIAL_ADMIN_PASSWORD` 환경변수를
12자 이상으로 설정하고, 데이터 이관을 마친 뒤에는 해당 환경변수를 제거합니다.

| 아이디 | 이름 | 역할 | 사업부 |
|---|---|---|---|
| Medpark0 | 시스템관리자 | 시스템관리자 (권한 11종 전부) | – |
| Medpark1 | 대표이사 | 임원 | – |
| Medpark2 | 김태현 상무 | 임원 | – |
| Medpark3 | 김홍윤 수석 | 재무담당 (수금 승인·업로드·마감) | – |
| Medpark4 | 박재흥 | 영업담당 | 덴탈 |
| Medpark5 | 김정훈 | 영업담당 | 메디컬 |

> 에스테틱 사업부 담당자 계정이 지정되어 있지 않아, 해당 거래처는 담당자가 `미지정`으로
> 표시됩니다. 계정·권한 관리에서 계정을 추가한 뒤 거래처의 담당자 값을 채우세요.

## 2. AI Space 배포

- 런타임: **python** (3.11)
- 데이터베이스: **없어도 됩니다.** DB 서버 없이 배포하면 SQLite 파일로 동작하고,
  나중에 PostgreSQL을 붙이면 코드 수정 없이 그쪽으로 전환됩니다
- 배포 공간: space_05

실행 명령은 `Procfile`에 정의되어 있습니다.

```
web: gunicorn -w 2 -k gthread --threads 4 -b 0.0.0.0:${PORT:-8000} --timeout 120 app:app
```

### 데이터베이스 연결
접속정보는 AI Space가 주입하는 환경변수를 그대로 씁니다.
**직접 설정할 필요가 없고, 코드에 하드코딩된 값도 없습니다.**

```
DB_HOST  DB_PORT  DB_NAME  DB_USER  DB_PASSWORD
```

`DB_BACKEND` 로 동작을 고정할 수 있습니다.

| 값 | 동작 |
|---|---|
| `auto` (기본) | `DB_HOST`가 있으면 PostgreSQL, 없으면 SQLite |
| `sqlite` | DB 접속정보가 주입돼도 무시하고 파일 DB 사용 |
| `postgres` | 반드시 PostgreSQL로 붙고, 안 되면 기동 실패 |

플랫폼이 MySQL 등 다른 종류의 접속정보를 주입해 버리면 PostgreSQL 드라이버가 접속에
실패해 컨테이너가 뜨지 않습니다. **그때는 `DB_BACKEND=sqlite` 를 넣으면 즉시 복구됩니다.**

현재 접속 대상은 `/health` 에서 확인합니다.

```json
{"status":"ok","db":"SQLite (/app/user_data/ar.db)","journal":"wal","time":"..."}
{"status":"ok","db":"PostgreSQL (psycopg2)","journal":null,"time":"..."}
```

`journal` 이 `wal` 이 아니면 저장 볼륨이 WAL을 지원하지 않는다는 뜻입니다. 동작에는 문제가
없고 동시 쓰기가 조금 더 직렬화될 뿐입니다.

### DB 서버 없이 운영할 때
아래는 워커 2개 · 스레드 8개로 실제 측정한 값입니다.

| 항목 | 결과 |
|---|---|
| 메모리 | 워커 2개 합계 약 75MB (space_05 한도 256MB) |
| 디스크 | 거래처 494건 기준 250KB (한도 1GB) |
| 동시 등록 | 120건 / 1.7초 / 충돌 0 |
| 동시 승인 | 120건 / 1.2초 / 잔액 정합성 일치 |
| 400행 업로드 | 0.01초 |
| 전체 조회 | 0.01초 / 응답 221KB |

이 규모에서는 SQLite로 충분합니다. PostgreSQL이 필요해지는 시점은 여러 서비스가 같은
데이터를 공유해야 할 때이지, 지금의 데이터량이나 사용자 수 때문이 아닙니다.

### 나중에 PostgreSQL로 옮기기
`migrate_to_postgres.py` 가 SQLite 데이터를 PostgreSQL로 옮깁니다.

```bash
export DB_HOST=... DB_PORT=5432 DB_NAME=ar DB_USER=ar DB_PASSWORD=...
python migrate_to_postgres.py            # 미리보기 — 무엇이 몇 건 옮겨지는지만 출력
python migrate_to_postgres.py --apply     # 실제 이관
```

8개 테이블을 모두 옮기고, 자동 증가 키의 시퀀스를 최대값 뒤로 재설정합니다.
이관 후 앱을 재기동하고 `/health` 의 `db` 값이 PostgreSQL인지 확인하세요.
원본 SQLite 파일은 지우지 말고 보관하는 편이 안전합니다.

테이블은 최초 기동 시 자동 생성됩니다. gunicorn 워커가 둘이므로 초기화가 겹치지 않도록
PostgreSQL 자문 잠금(`pg_advisory_xact_lock`)을 걸어 두었습니다.
컨테이너가 DB보다 먼저 뜨는 경우를 대비해 최대 30초까지 접속을 재시도합니다.

### 영속성
| 대상 | 위치 | 재배포 시 |
|---|---|---|
| 거래처·수금·목표·계정 | PostgreSQL 또는 `/app/user_data/ar.db` | 유지 |
| 세션 서명 키 | `/app/user_data/secret_key` | 유지 |

`/app/user_data/` 는 AI Space에서 재배포 후에도 보존되는 유일한 경로입니다.
**절대 다른 위치로 바꾸지 마세요.**

`update_project`로 코드만 갱신하면 데이터는 그대로입니다.
프로젝트 삭제는 DB까지 지웁니다. 사전에 `backup_project`를 받으세요 (DB 덤프가 자동 포함됩니다).

### 시각 처리
서버 시간대가 UTC여도 화면에는 한국 시각이 나오도록,
등록·승인·업로드 시각은 `now() AT TIME ZONE 'Asia/Seoul'` 로 저장합니다.

### 환경변수 (선택)
| 이름 | 기본값 | 설명 |
|---|---|---|
| `SECRET_KEY` | 자동 생성 | 세션 서명 키. 지정하면 재배포 후에도 로그인 세션이 유지됩니다 |
| `AR_INITIAL_ADMIN_PASSWORD` | 없음 | 빈 DB에서 최초 관리자 계정을 만들 때만 사용하는 12자 이상 임시값 |
| `PORT` | 8000 | 수신 포트 |

### 외부 의존성
브라우저가 다음 세 가지를 CDN(`cdn.jsdelivr.net`)에서 내려받습니다.

- React 18 / ReactDOM 18 — 화면 렌더링
- SheetJS 0.18 — 엑셀 파싱
- Pretendard — 한글 글꼴 (실패해도 시스템 글꼴로 대체됨)

사내망에서 이 도메인이 막혀 있으면 로그인 화면 대신 안내 문구가 뜹니다.
그 경우 해당 파일들을 `static/`에 내려받아 두고 `templates/index.html`의 script 경로만 바꾸면 됩니다.

## 3. 화면과 권한

권한은 11종이며 계정마다 개별 지정합니다. 역할 템플릿(시스템관리자 / 임원 / 재무담당 / 영업담당)을
누르면 해당 조합이 한 번에 채워지고, 이후 체크박스로 조정할 수 있습니다.
권한이 없는 화면은 좌측 메뉴에 아예 나타나지 않습니다.

| 화면 | 필요 권한 | 하는 일 |
|---|---|---|
| 대시보드 | `dashboard_view` | KPI 4종, 사업부별 채권 분류, 월별 수금 실적, TOP5, 수금목표 요약, 담당자별 현황 |
| 거래처별 현황 | `customer_view` | 사업부 → 채권분류 2단계 트리, 검색, 비고 인라인 편집 |
| 담당자별 채권현황 | `owner_view` | 담당자별 잔액 구성과 담당 거래처 목록 |
| 수금 등록 | `collection_register` / `collection_approve` | 영업담당 입력 → 재무담당 승인 후 잔액 반영 |
| 수금목표 관리 | `target_manage` | 목표일·완료일·수금방법·담당자·비고 |
| 출고 데이터 업로드 | `upload_data` | 엑셀 업로드, 월 단위 교체, 업로드 이력 |
| 계정·권한 관리 | `user_manage` | 계정 생성·정지, 비밀번호 재설정, 권한 편집 |

나머지 권한: `note_edit`(비고 편집), `month_lock`(마감 잠금·해제), `data_export`(내보내기).

### 수금 처리 흐름
등록된 수금 건은 `승인 대기` 상태로 들어가며, **승인 시점에만** 거래처 잔액이 줄어듭니다.
잔액이 0이 되면 채권분류가 자동으로 `정상`으로 바뀝니다. 반려하면 잔액은 그대로입니다.
같은 건을 두 번 승인할 수 없습니다.

## 4. 엑셀 업로드 규칙

첫 번째 시트를 읽습니다. 앞쪽 15행 안에서 `거래처코드`와 `거래처명`이 함께 있는 행을 머리글로 잡으므로,
제목 행이나 빈 행이 위에 있어도 됩니다.

인식하는 열 (괄호 안은 같이 인식되는 이름):

| 항목 | 열 이름 |
|---|---|
| 거래처코드 | 거래처코드 (코드, 고객코드) |
| 거래처명 | 거래처명 (거래처, 업체명, 고객명) |
| 사업부 | 사업부 (사업부문, 부문) |
| 채권분류 | 채권분류 (분류, 채권상태, 상태) |
| 담당자 | 담당자 (영업담당, 담당) |
| 미수잔액 | 미수잔액 (미수금액, 채권잔액, 잔액, 미수금) |
| 선수금 | 선수금 (선수금액) |
| 경과일 | 경과일 (연체일, 경과일수, 연체일수) |
| 최종수금일 | 최종수금일 (최근수금일, 최종입금일) |
| 비고 | 비고 (특이사항, 메모) |

자동 처리되는 것들:

- 채권분류 열이 비어 있으면 경과일로 판정합니다 — 30일 이하 `정상`, 180일 이하 `연체`, 그 이상 `부실`
- 거래처코드가 비었거나 `#REF!`, `#N/A` 인 행은 건너뜁니다 (원본 엑셀의 VLOOKUP 오류 대응)
- 같은 코드가 두 번 나오면 마지막 값으로 덮어씁니다 (중복 행 대응). 업로드 전 미리보기에 건수가 표시됩니다
- 금액의 쉼표는 제거하고 숫자로 읽습니다

### 월 단위 교체
업로드는 **선택한 기준월의 데이터만** 교체합니다. 다른 월 데이터는 건드리지 않습니다.
같은 달을 다시 올리면 그 달 것만 새 파일로 바뀝니다.

### 마감 잠금
잠금은 **수동입니다.** 날짜가 지났다고 자동으로 잠기지 않습니다.
`month_lock` 권한이 있는 사람이 직접 잠그고 직접 해제합니다. 잠긴 달은 업로드가 거부됩니다.

## 5. 로컬에서 실행

```bash
pip install -r requirements.txt
python app.py          # http://127.0.0.1:8000
```

`DB_HOST` 가 없으면 SQLite 파일(`user_data/ar.db` 또는 `/app/user_data/ar.db`)로 동작하므로
PostgreSQL 없이도 그대로 띄워볼 수 있습니다. 로컬에서 PostgreSQL에 붙이려면:

```bash
export DB_HOST=localhost DB_PORT=5432 DB_NAME=ar DB_USER=ar DB_PASSWORD=...
python app.py
```

SQL은 PostgreSQL 문법 한 벌만 관리합니다(`%s` 자리표시자, `ON CONFLICT`, `RETURNING`).
SQLite로 실행할 때는 `db.py` 가 자리표시자만 `?` 로 바꿔 같은 쿼리를 돌립니다.

## 6. 화면 코드를 수정할 때

브라우저에서 실행되는 파일은 `static/app.js` 이고, 사람이 읽고 고치는 원본은 `static/app.jsx` 입니다.
JSX를 고친 뒤에는 반드시 다시 컴파일해야 화면에 반영됩니다.

```bash
npx tsc static/app.jsx --jsx react --target es2018 --outDir /tmp/out --skipLibCheck
cp /tmp/out/app.js static/app.js
```

타입 관련 경고(TS7006, TS18046 등)는 무시해도 됩니다. 그래도 파일은 정상적으로 생성됩니다.

> 브라우저에서 JSX를 실시간 변환하지 않는 이유: Babel standalone은 약 3MB이고 화면을 열 때마다
> 1,300줄을 다시 변환합니다. 미리 컴파일해 두면 첫 화면이 눈에 띄게 빨라집니다.

## 7. 파일 구성

```
app.py               라우팅, 인증, 권한 검사, REST API
migrate_to_postgres.py  SQLite → PostgreSQL 이관 (나중에 DB 도입할 때 1회 실행)
db.py                DB 방언 처리(PostgreSQL/SQLite) · 스키마 · 권한 정의 · 계정 시드
seed.py              시연용 거래처 데이터 (실데이터 업로드 시 교체됨)
wsgi.py              WSGI 진입점
Procfile             gunicorn 실행 명령
requirements.txt     Flask, gunicorn, Werkzeug, psycopg2-binary
templates/index.html HTML 셸
static/app.jsx       React 원본 (수정용)
static/app.js        컴파일 결과 (브라우저가 실제로 읽는 파일)
static/styles.css    디자인 토큰과 레이아웃
```
